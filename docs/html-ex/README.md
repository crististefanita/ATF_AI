## Current Canonical Lessons

- The application owns the graph; the package is only the overlay.
- `Business Flow Graph` should be the only default-open main section.
- `Score Overview` is computed cold, not decorated.
- `Overall` is capped by business substance, proof class, and contract failures.
- `root diff` and `run diff` are primary evolution truth.
- `run-state.json`, `package-state.json`, `execution-gate-card.md`, render proof, link audit, XML/result proof, MCP gate, and final report links form the artifact spine.
- MCP green is required, but never enough: the business object must still be product-owned and UI-visible.
- MCP artifacts must be frozen as a coherent final set: gate result, XML, Extent, and report links should describe the same final rerun.
- `tests produced` and `runs consumed` do not mix.
- A final HTML report must not mention `html-ex`, `teacher`, `benchmark`, or external calibration language.

## What The Library Must Not Teach

- Do not copy the business object from any example.
- Do not raise Overall because the page looks good.
- Do not raise Overall because MCP is green.
- Do not treat shell/gateway/green-test proof as durable ownership.
- Do not turn setup into the business object.
- Do not hide weak proof class behind polished HTML.
- Do not sell one durable family as full application closure.

## Cold Calibration Formula

A package is mature only when this chain is complete:

`claim -> source -> run diff -> state -> execution result -> MCP artifact -> report link -> score cap`

If MCP contract tests show blockers, the package is not positive-teacher grade, even if the report is visually strong.

If the package owns only one business family, `Overall` must stay capped even when all artifacts are clean.
