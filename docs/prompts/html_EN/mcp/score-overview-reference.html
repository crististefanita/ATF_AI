1.4.1 MCP candidate threshold MCPMCP-valid does not mean html-ex-ready
ValueRoleConsequence
RUN_EXPECTED_DELTA_QUALITYruntime quality threshold on a scale of 0-100it is read from agent-runtime.properties, is not hardcoded and is not converted to the old 8.50 scale
run keptcalibrate actual_delta_quality, if the value is publishedbelow the threshold must be explained as partial / blocker / rerank
candidate html-exminimum threshold for Overall and capbelow the threshold means FAIL candidates, even if the package is MCP-valid
Overallfinal score publishedit must be below or equal to the cold head
capbusiness substance ceilingif it is below the threshold, the package is not teacher-ready
Overall does not receive credit for narrative claims without executed action. The score follows the strongest business object proven by source action and proof trace.
  • The same constant has two applications: run-level quality and candidate-level teacher threshold.
  • testng-mcp-full.xml is health/diagnostic and can be green without making the package teacher-ready.
  • testng-mcp-package-closeout.xml decides whether the package is MCP-publishable: Extent/XML/ledger/gate/origin complete, with 0 failures, 0 errors, and 0 skipped in the final profile.
  • testng-mcp-candidate.xml is separate promotion and must fail when Overall or cap are below the threshold.
  • Candidate/html-ex is a separate promotion over publishability; does not repair or replace the MCP close-out.
  • This protects honesty: technically valid does not mean library example.
