2.3 Single run cycle what each run must do
What must remain in mind
  • The run must leave the re-openable proof: diff, proof, state and lesson.
  • What is not saved to disk cannot be safely used by the next agent.
  • Without diff, proof and running status, the cold fixation is not complete.
  • A run explains the active target or public defect / severe blocker.
  • Decisive learning should be saved to disk, not left in chat.

  • MCP does not validate the concrete business of the application.
  • MCP validates that the proof is real, re-openable and aligned with the architecture.
  • In the end, the agent does not close until he has testng-mcp-package-closeout.xml run on the frozen package, with 0 failures, 0 errors, and 0 skipped in the final subcollection.
  • If validation/mcp or final-report links are synchronized after close-out, run testng-mcp-post-sync-smoke.xml: 0 failures, 0 errors, 0 skipped.
  • When the agent declares there are no more artifact-spine changes planned, run testng-mcp-final-report-closeout.xml exactly once; if it fails, repair only the public report/link/sync surface and rerun the same profile.
  • After final-report surface close-out is green, run testng-mcp-langgraph-final-report.xml; if it fails, repair only analysis/langgraph-business-understanding.html semantics/links unless it exposes stale frozen evidence.
  • If the package is an html-ex candidate, run testng-mcp-candidate.xml after that, so promotion does not hide package close-out issues.
  • The number of MCP tests is not global. It belongs to the profile and the MCP version: 90, 89 or 102 can only be correct if the report names the profile, the order and the ledger that explains them.
2.4 Grouping rule in the same runwhen an area deserves more tests
If you got herejudgeGood form
page / status / functionality with distinct business behaviors maybe the same anchor closes the active target without mechanical sweep? group related tests in the same run
the anchor that cannot support the active target real blocker or wrongly chosen border? public defect / severe blocker and rerank
area with another business identity or other proof does separation help clarity, isolation or rerank? split only if the new run can close the active target
Legend
  • Good example: same area favorites can produce empty-state, persistence, and collection behavior in the same run if they all come from the same functional anchor.
  • Bad example: five close variants of the same click or the same blocker just to inflate the number.
  • The good grouping is based on functionality and business truth, not on the convenience of implementation.
  • At the end of each run: tell if the active target was closed.
  • If not: the verdict is defective or a severe blocker.

  • Diff is the primary truth of evolution.
  • File snapshots are supported.
  • The agent's explanations are support.
  • source-delta-carrier.md explains the selection or meaning of the diff.
  • If the diff is missing, the carrier does not save the claim.

  • It says the historical change compared to the previous border.
  • The diff remains truly primary.
  • The summary just makes it reopen quickly.
